## 一、选题①沉淀（v1→v21，最大踩坑场）

### 1.1 开场迭代（三个大坑）
- **拉踩**：v1"你选错了一个，三年后带不走"=预设 WorkBuddy 是错。→ 改"这题没有标准答案，但大多数人选的方式是错的"——**攻击行为（比参数），不攻击产品**。
- **中立摇摆**："两边都有理，我不站队"=告诉观众"自己看"，没留人理由。→ **开场立判，但不拉踩**。
- **两套标准互搏**："选工具=选老板"（批判视角）vs"你要开什么店"（开店视角）并存=观众不知道记哪个。→ **统一到"你要开什么店"一条线**，判断句只在收尾出现一次。

### 1.2 比喻纪律
- **一个比喻世界贯穿到底**：铁匠铺/家电清单/支线/流水线/中央厨房全删——它们属于别的世界，观众画面会断。餐厅世界只留：点菜/出餐/后厨/菜谱/料包/供应链/配方/灶台/厨具/试菜/菜谱本。
- **比喻映射要对准真实场景**："提交总部审核收录"是技能开发者投稿场景，企业用户根本没有——张冠李戴，懂行的一眼看穿。
- **概念背后的真实逻辑先想通**：
  - "手艺归谁"：手艺跟着人走（归你），不归你的是**菜谱/供应链/配置**（店里的）。所以是"**光有手艺不够**"，不是"手艺不归你"。
  - "带不走"双重标准：说加盟店配置带不走是缺点，却暗示自营店零成本迁移——**两边换平台都有迁移成本**，差别只在"东西在谁手里、规则谁定"，不在"能不能带走"。

### 1.3 事实硬伤（全部被当场抓，都进教训）
| ❌ 错误 | ✅ 修正 |
|---|---|
| 缓存有"开关" | 缓存是自动/代码标记，没有开关 |
| WorkBuddy"调参数" | 大部分参数不对普通用户开放——"能调的就那几样，出厂定死" |
| 加盟店"自动接单自动配菜" | 工具是主动用的，不是全自动——"流程是现成的，你照着走" |
| 自营店"现场就能改流程" | 自营的改要付出成本（自己调试验证）——"自己调配方，调不好没人帮" |
| 未核实断言 | "配置存在总部系统里"（存储位置无一手证据）→ 只讲"绑在这家店体系里，带不走"（迁移成本） |

### 1.4 立场对称（讲一方好必讲一方代价）
| | 加盟店（WorkBuddy） | 自营店（DSH） |
|---|---|---|
| 控制权 | 看不见改不了——**但不用你懂，不容易抓瞎** | 全透明可改——**但全自己管，没人兜底** |
| 方法论 | 攒不下配套——**但有标准菜谱/料包/供应链安全网** | 全是自己资产——**但路自己趟，坑自己踩** |
| 工具链 | 只能等官方——**但坏了有人管，有售后** | 自己添设备——**但坏了自己修，没售后** |

**"没有谁更好"不是结尾口号，是结构上就成立**（每层镜像对称）。

### 1.5 术语双轨
不能 0 术语（观众总得学点啥），但术语首现必须带人话解释。闭环：**P1 引入（带解释）→ 各层收口（复述）→ P10 总结（串讲）**——引入→复用→总结，观众带走真概念。

### 1.6 分页与故事
- 一页一个任务一个记忆点；过渡页太薄（一句3秒）就并入相邻页开头。
- 故事页=三层差别的具体化，**不写技术细节**（"改后厨工序/厨师小组试菜"太极客，普通观众听不懂）；故事要**把好处坏处都演出来**（P11 演省心+店不是你的，P12 演自由+累全靠自己）。
- 减厚：删解释性铺垫/免责声明/双概念句，只留"是什么+多少钱+怎么办"。

## 二、token 收费稿沉淀（番外）

### 2.1 世界观（术语=比喻双轨的典范）
备菜（输入）/ 出菜（输出）/ 常备菜（缓存命中）——术语和比喻一一映射，观众一边听懂一边记住。

### 2.2 数字口径
- 9 / 27 / 0.3（百万 token）= **DeepSeek 高峰价**，错峰半价——必须交代"谁的、什么时段"。
- 饭点结束时间官方只写了开始（9:00 / 14:00），**结束时间没核实就不写死**（"白天那几个小时"）。

### 2.3 逻辑链（最大的坑）
"输出贵 3 倍，白花却都在输入"——**必须补"输入的量远大于输出"（历史/重复资料）**，否则"白花在输入"站不住，被挑战。

### 2.4 行动指令可执行
- "固定前缀"是机制（把不变部分放最前，缓存命中），**不是"开关"**——开关不存在，念出来就是硬伤。
- 概念简单 ≠ 执行简单：S6"方向就一句话"（概念）、S8"前缀差一个字都不算数，人手容易漏，靠工具锁格式"（执行）——分层讲，不矛盾。

### 2.5 别重复讲三遍
错峰规则（饭点加价）和错峰行动（白天挪晚上）**分开放**，各讲一遍。

### 2.6 人群分层给步骤
第一步所有人（缓存）→ 第二步重度用户（错峰）→ 第三步团队/开发者（模型路由 LiteLLM）→ 第四步烧钱大户（压缩 Headroom/批处理）。**每步标明适用人群**，观众对号入座，避免"都让我做"。

## 三、多模态震惊体沉淀（起猛了·快讯）

### 3.1 情景是画面，不是台词
睡衣/周六中午/刚睡醒 = **镜头交代，不口播念**。口播只留"起猛了"——观众用眼睛看状态，用耳朵听震惊。

### 3.2 原创边界（被当场纠正）
学大V的**情绪节奏/感觉**可以，**抄原文表达和框架不行**（"你品品""还剩多少"都是别人的话）——借情景和情绪，用自己的话重构信息。

### 3.3 场景对号入座是观众，不是作者
"产品图/知识图谱/流程图"是**作者身份**（PMO/创作者），不是观众痛点。观众对号入座的是"**你是不是也遇到过：一张图摆在面前，想让 AI 看懂，它却只能干瞪眼**"。更狠的一招：**如果例子选什么都不对，就删掉它**——震惊体短句快切一口气，注脚只会拖节奏。

### 3.4 删废话
"习惯性刷一眼手机"与"起猛了"重复——删。"了"的纪律：删字不牺牲人话（"现在不用了，直接看图"才对，不能删成"现在不用，直接看图"）。

### 3.5 数字口径（这条分支第 N 次验证）
- "逼近 Opus 4.8"，不是"持平"（全部报道口径是逼近）。
- "成本低 99%"（相对 Opus 4.8），挂对比对象才成立；"1 块钱 vs 1 分钱"要说"同样的视觉能力"才不被挑战。
- 用真实场景替代编造：以前用小龙虾调它只能读写文字、看图要配视觉模型/OCR——**现在不用了，直接看图**（观众=用 agent 工具的人，一听就懂）。

## 四、选题池评审沉淀（热点×翻译）

### 4.1 框架
热点×翻译=抓热点，但**翻译成对观众的洞察**，不是跟风复述新闻。15 秒答案：把热点翻译成"这对你（观众）有什么用"。

### 4.2 分类是账号的分水岭
- **A 类科普翻译**（企微 MCP=AI 的 USB 接口、蒸馏是什么）→ 涨粉/收藏健康。
- **B 类行业观察**（Anthropic 增速放缓、特斯拉接豆包）→ 容易做成围观，涨粉差；除非转成"对你选模型意味着什么"。

### 4.3 数据底座（修正后）
- 选谁稿 = 5,627 播放 / +20 粉（历史最高单条转化），1.1 万是图文曝光——**复盘前先核实数据，别拿错数字下结论**。
- Harness 到底是啥 = 10,042 播放 / 82 收藏——**纯科普翻译型**，这才是"翻译官"路线的数据底座。
- 结论不变：**科普翻译型 > 争议围观型**（收藏/转化健康）。

### 4.4 增量建议
- MCP 用**亲历者视角**讲（自己跑 OpenClaw+企微插件，"我踩过的接口坑"）——观众带走概念+避坑。
- 豆包三件套**卡发布当天发**，时效窗口就是价值。
- 已做过的题（token）只讲增量（MoE 为什么便宜），且**标"系列第 N 期"**，别当新选题。

## 五、B站数据复盘沉淀

- **结果指标 vs 过程指标分开看**：播放（结果）vs 收藏/弹幕/平均播放占比/封面点击率（过程）。
- **收藏/播放比 = 内容被留下来的能力**（token 1%、选谁 0.25%、开店 1.9%）。
- **平均播放占比 = 留人能力**（开店 5.45% vs token 2.66%，长视频都要盯前 3 秒）。
- **吸粉量 = 健康信号**：播放高吸粉低 = 围观（争议引流不转化）；播放中吸粉高 = 范本。
- 健康范本特征：看完多（占比高）+ 收藏多 + 涨粉多——**往"讲透一个有用知识点"方向做，不往"争议话题"方向做**。

## 六、通用自检清单（17 条，跨所有选题）

### 事实层（能不能被挑战）
1. 数字必须带口径（谁的、什么时段、对比基准）。
2. 行动指令必须可执行（指令不存在 = 信任崩塌）。
3. 场景必须对准真实对象（企业用户≠开发者投稿）。
4. 对比必须对称（说 A 缺点必须给 B 对应代价）。

### 逻辑层（左右脑不互搏）
5. 一集一个答案（判断句只在收尾出现一次）。
6. 立场从头到尾一致（说"没有谁更好"就不能把一方说一无是处）。
7. 攻击行为，不攻击对象（对立面是"比参数"，不是某产品）。
8. 概念背后的真实逻辑先想通（手艺归谁/能不能带走，先搞清事实再设计对仗句）。

### 表达层（受众能不能懂）
9. 一个比喻世界贯穿到底（餐厅就是餐厅，禁混入家电/铁匠铺）。
10. 术语和比喻双轨（术语带走知识，比喻负责听懂）。
11. 类比深度匹配受众（抖音：后厨谁说了算/攒的菜归谁/厨具是不是自己的）。
12. 开场只做一件事（对抗/立判/抛问题三选一，3 秒内）。
13. 删掉不增加信息的句子（过渡腔、重复句全删）。
14. 互动不指挥观众（"评论区打 XX"是运营腔）。

### 流程层（怎么保证前面三条）
15. 交付前主动自查（技术人审查+普通人听感双视角），不等别人挑。
16. 每轮修改前先列"不可动清单"（术语/数字/口径/比喻世界）。
17. 一版只解决一个反馈（别顺手"优化"别处，顺手改最易引入新互博）。

## 一句话总纲（全系列）

> **判断句立判、事实句收窄；比喻一个世界贯穿、术语双轨带解释；立场镜像对称、两边都讲代价；开场只做一件事、连载每期一个增量；数字带口径、没核实不写死；交付前主动自查、一版只改一个点。**
